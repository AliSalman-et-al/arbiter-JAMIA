Investigation date: 23 October 2026. Scope: documentary and implementation inspection; no assessment, statistical analysis, verification campaign or manuscript build was rerun. Only this document was written.

## Evidence boundary and writing contract

The clinical reader needs to understand how a judgment can be traced from a specified trial result through source evidence and signalling answers to a domain rating. The supported mechanism is the separation of document selection, model interpretation and software rule execution. Its boundary is equally important: authenticated source text and reproducible rule application do not establish a correct clinical interpretation or explain any observed agreement gain.

## Source-backed mechanism sequence

1. **Fix the assessment target before domain work.** The model proposes the trial result, with source evidence; the workflow has a separate result-approval gate. Interactive approval gives the reviewer an opportunity to correct the target before downstream judgments. In the evaluated run, the harness approved the proposal unchanged with `rob2 review` and resumed with “Approved.” This preserves a target for subsequent checks but does not independently establish that the model selected the intended outcome, comparison, time point or analysis. It is not evidence of human clinical review in the benchmark. [Runner][runner] [Run setup][run]

2. **Capture documents and distinguish file identity from extracted-text identity.** Intake stores source bytes. A source identifier incorporates trial identifier, logical path and file digest; metadata separately records the file SHA-256 and a text-projection hash. The projection hash includes the extraction recipe, source digest, media type and hashes of each extracted page. PDF text is extracted with PyMuPDF, normalized, and may include appended Markdown table representations. Before evidence operations, software checks captured bytes, page sequence/count and projection identity against the authoritative source metadata. This detects stale or inconsistent material relative to that capture. It cannot show that the captured document belongs to the correct trial, is the latest document, reports true facts, or was extracted without loss of layout or meaning. “Exact quotation” here means exact text from the captured extraction, not a typographically identical PDF facsimile. [Extraction and identities][state] [Projection verification][projection]

3. **Select source passages through tools rather than accept an unconstrained quotation field.** Reading and searching return passage references. The model can reuse a reference, select a page/line range, or supply copied `selected_text` to locate a narrower contiguous passage. The latter input is matched to captured page text with presentation normalization; unmatched or ambiguous wording is rejected. The MCP copied-text route restricts matching to the specified physical page and checks reading delivery. The stored quotation is always derived from `page_text[start:end]`, with trial/source identifiers, page, character offsets, source version and line bounds. Subsequent handle validation checks quotation equality against that page slice. This excludes unmatched model-generated wording from an accepted **text evidence record through this pathway**. It does not prevent selection of an irrelevant, misleadingly short or incorrectly scoped real passage; model-written justifications can still be wrong. The literal statement “the model never types quotation text” would be inaccurate because the copied-text locator is supported. [Tool contract][text-tool] [Text selection][text-selection] [Handle validation][handle-validation]

   **Evaluated artifact check:** in the [AVATAR bundle][avatar], member `evidence/05e667d2d41d385843fce8092c896af651d2f651bcfdc8a7fd1d2841801879af.json` records `kind=narrative`, physical page 9, `start=5162`, `end=5702`, line bounds 76–83, a `source_id`, `source_version`, content identity and returned handle. Its quotation retains extraction line breaks. `canonical.json` separately contains the source file hash and projection hash, signalling answers, evidence links and model justifications. These fields corroborate the exported representation; their presence alone is not a new comparison with the PDF.

4. **Use a separate visual pathway when layout carries meaning.** Rendered pages are associated with source/page identifiers, a rendering identity, a PNG hash and a delivery receipt. A visual evidence record adds normalized region bounds and a model-written transcription, optionally with uncertainty. Software checks receipt/source consistency and region bounds; the whole-page route can mark text corroboration when the transcription also matches extracted text. General image understanding is not independently verified. This prevents an accepted visual reference from silently pointing to an arbitrary source or invalid region under the checked route; it cannot establish that the transcription reads the correct row, denominator, arrow or footnote. [Visual selection][visual]

   **Evaluated artifact check:** the [Aboelfadl bundle][aboelfadl], member `evidence/723b630ffc8d7410c77d6198c3571a02b8ff19d8f351cb4e1f3124d658e0fb3f.json`, contains a page-5 render, PNG hash, delivery receipt, region `[0.2, 0.05, 0.95, 0.55]`, `provenance=host_visual`, transcription and uncertainty. This is a provenance-linked model transcription, not a software-extracted quotation.

5. **Record the model's interpretation explicitly.** Domain submissions contain permitted signalling answers, evidence bases and justifications, with fields for unknowns and counterevidence. Source references must resolve within the trial; the software copies evidence text into the canonical basis. The schema distinguishes direct support, indirect support, inference, context and contradiction; unresolved premises can have limitations and scoped zero-hit search receipts. These distinctions make inferential steps and unresolved information inspectable. A zero-hit search establishes only failure of that query against captured searchable text, not absence of the fact from all trial materials. Required-path and reference checks cannot determine whether a passage substantively supports the answer. [Evidence instructions][evidence-guide] [Domain submission][domains]

6. **Compute a proposal, then preserve any departure separately.** Software applies `evaluate_domain` to the recorded active answers and retains its proposed label and rule trace. The adopted label defaults to that proposal. A different adopted label requires adjudication tied to an existing checkpoint, unchanged answers and evidence already cited by that checkpoint; the schema requires a nonblank rationale, supporting evidence and assessor attribution. Attribution defaults to “assessing model” and is explicitly not researcher approval. This prevents an override from silently replacing the algorithmic proposal, while allowing a recorded departure. It does not validate the departure's rationale or correct erroneous answers. [Domain submission][domains] [Adjudication schema][adjudication]

   The AVATAR `canonical.json` contains separate `proposed`, `adopted`, `authority`, `adjudication` and `trace_authority` fields; its current domain records use algorithm authority with null adjudication. Study code checks proposed labels against recomputed rules, adopted labels against analyzed outputs, and override records separately. The retained benchmark report records no domain overrides. Therefore proposal conformance is a software property; absence of overrides and adopted-label conformance are benchmark observations, not an unconditional guarantee about every future adopted judgment. [Proposal/adoption checks][decision-check] [Retained benchmark account][retained-methods]

7. **Export an inspectable record and keep three checks distinct.** The inspected bundles contain canonical assessment JSON, claims, evidence records, a manifest and a verification receipt; their inventories do not include original PDFs or rendered PNG files. The retained fresh-verification report describes rereading archive bytes and recomputing bundle invariants rather than trusting the stored receipt. Separately, the study's quotation-binding function checks source membership and the presence of text, source version and ordered offsets; its image branch checks source/page/render fields and valid region bounds. It does **not** reopen source documents or compare quotation content with original page text. Do not collapse (a) runtime source-slice validation, (b) bundle integrity/derivation verification and (c) the study's structural binding audit into a claim that every quotation was independently re-extracted from its PDF. None of these checks establishes semantic support for a signalling answer. [Binding audit code][binding] [Fresh-verification provenance][reverification] [Public bundle verifier][verifier]

## Proposed System design prose

*Proposed subsection: 332 words, excluding source markers. Evidence markers are development annotations, not proposed manuscript reference numbers.*

ARBITER separates interpretation of trial evidence from application of the RoB 2 decision rules. The model identifies the result to assess, examines the available documents and answers the signalling questions; software computes the domain ratings implied by those answers. A result-approval step allows an interactive reviewer to inspect the proposed target before domain assessment. In the automated benchmark, the harness accepted that proposal unchanged. [run]

Source documents are retained with cryptographic hashes identifying their contents. Extracted page text has a separate version identifier, allowing passages to be linked to the captured document and extraction. The model selects evidence through document-reading and search tools, using returned passage references, page and line ranges, or copied text that must match a source passage. Software stores the selected text directly from the captured page, together with its source, page and character offsets. Thus, the accepted text evidence is a source selection rather than an unchecked model-written quotation. This constrains fabrication of quotation wording within the text evidence pathway, but does not establish that the passage is relevant, complete or correctly interpreted. Errors in document extraction can also persist. [state] [text-tool] [text-selection] [handle-validation]

For figures and other material requiring visual interpretation, evidence records link a rendered source page and selected region to a model-written transcription. These links identify the inspected image; they do not independently verify its transcription or interpretation. Each signalling answer records its evidential basis and justification, with provision for uncertainty and counterevidence. Software checks answer options, required question paths and evidence references before applying the decision algorithms. [visual] [domains]

The algorithm-derived proposal and adopted domain rating are recorded separately. A departure requires a documented rationale and supporting evidence linked to the saved answers, preserving the distinction between rule execution and subsequent judgment. Proposed and adopted ratings were checked separately in the evaluation. The exported assessment record retains evidence links, answers and decision traces for inspection. These controls support traceability and reproducible rule application; they cannot establish that the evidence justifies the signalling answers or that the resulting assessment is clinically correct. [adjudication] [decision-check] [binding]

## Editorial decisions and unresolved facts

- Prefer **“software stores text selected from captured documents”** to “the model cannot hallucinate citations” or “the model never types quotations.” The supported safeguard concerns the accepted evidence text, not all generated prose or all citation errors.
- Explain the model/software division before hashes and handles. Keep implementation identifiers in eMethods or the provenance note; clinical readers need the transformation and its limits.
- Describe safeguards as mechanisms, not demonstrated causes of improved agreement. No component ablation or new causal analysis was performed here.
- Preserve the evaluated/public distinction. A concise manuscript account can use ARBITER as the system name while eMethods explicitly identifies both revisions and the scope of the retained comparison.
- Original development rationale, prompt-selection history, benchmark overlap and reviewer benefit remain unestablished by this inspection. No chronology or efficacy claim has been supplied to fill those gaps.
